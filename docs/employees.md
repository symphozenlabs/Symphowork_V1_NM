# Employees

Users remain authentication identities; employees are organization HR records; memberships grant organization access. Employees can exist without a linked user account and are linked only through the secure employee invitation flow.

Employee IDs are generated by atomically incrementing `organizations.employee_id_next` inside the employee-creation transaction. This avoids count/max race conditions. Employee updates create both an audit record and a human-readable `employee_history` event.

Employee list queries are organization-scoped, paginated, and searchable by employee ID, display name, and work email. Future filtering should remain server-side.
